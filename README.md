# General Insurance Loss Reserving: Chain-Ladder + Bornhuetter-Ferguson + Bootstrap

A portfolio project applying core P&C actuarial reserving methods to **real** NAIC Schedule P /
CAS Loss Reserving Database data — not synthetic or textbook numbers.

**Line of business:** Commercial Auto Liability
**Company:** State Farm Mutual Automobile Insurance Group (NAIC Group Code 1767)
**Experience period:** Accident years 1988–1997, evaluated through 10 years of development

## The problem

An insurer collects premium today for claims that can take years to fully report and pay.
At any valuation date, only the *paid-to-date* portion of each accident year's losses is known
with certainty — the rest (still-unpaid claims, including ones not yet even reported) has to be
**estimated**. That estimate is the loss reserve, and getting it wrong in either direction is
a real solvency and pricing risk. This project estimates that reserve for a real 10-year book
of commercial auto business using two industry-standard methods, then quantifies how uncertain
that estimate actually is.

## Files

| File | What it is |
|---|---|
| `Loss_Reserving_Model.xlsx` | The core model. Five sheets: `README`, `Triangle_Data` (raw inputs), `Chain_Ladder` (development-factor method, fully formula-driven), `Bornhuetter_Ferguson` (BF method), `Summary` (comparison + chart). Every number is a live formula — change the tail factor or the a priori loss ratio assumption and everything downstream recalculates. |
| `Reserve_Bootstrap.py` | Python script implementing an ODP (Over-Dispersed Poisson) bootstrap (England & Verrall, 2002) — 10,000 simulations that turn the single-point Chain-Ladder estimate into a full probability distribution for the reserve. |
| `reserve_distribution.png` | Histogram of the simulated reserve distribution, generated by the script above. |
| `bootstrap_results.csv` | Raw output of all 10,000 simulated reserve totals. |
| `Actuarial_Memo.pdf` | A written reserving memo (the actual deliverable format used in practice) documenting methodology, results, judgment calls, and limitations. |

## How to reproduce it

```bash
# 1. Get the raw data (CAS Schedule P, commercial auto, via a GitHub mirror
#    of the original casact.org files)
git clone --depth 1 https://github.com/problemofpoints/reservetestr.git

# 2. Filter to this company's commercial auto triangle:
#    GRCODE == 1767, calendar_year <= 1997

# 3. Run the bootstrap simulation (~2 minutes for 10,000 iterations)
python3 Reserve_Bootstrap.py
```

The Excel model and the memo PDF are committed as finished artefacts; the scripts that
generated them are not part of this repo. `Reserve_Bootstrap.py` is the one script here and
it runs standalone against the extracted triangle.

Requires: `pandas`, `numpy`, `matplotlib`.

## Headline result

| | Amount ($000s) |
|---|---|
| Paid losses to date | 1,872,675 |
| Chain-Ladder reserve estimate | 433,215 |
| Bornhuetter-Ferguson reserve estimate | 450,395 |
| Bootstrap 90% confidence interval | 408,651 — 457,846 |
| Company's own booked reserve | 360,657 |

Both independent methods — and the entire simulated 90% confidence range — sit above the
company's booked reserve. That gap is the interesting finding of the whole exercise: it's
exactly the kind of signal that would trigger a deeper reserve review in a real actuarial
department, and it's discussed in full in `Actuarial_Memo.pdf`, Section 4.3.

## Methods, in one line each

- **Chain-Ladder**: assumes the future develops the way the past developed — projects each
  accident year's ultimate loss using historical development factors observed for older,
  more mature years.
- **Bornhuetter-Ferguson**: blends the Chain-Ladder's signal with an independent, premium-based
  prior expectation, weighted toward the prior for the least mature (least credible) years —
  fixes Chain-Ladder's instability for recent accident years.
- **ODP Bootstrap**: resamples the model's own residuals thousands of times to simulate
  parameter uncertainty, then layers on simulated process (random claims-payment) uncertainty,
  turning one reserve number into a full distribution — the same Monte Carlo logic used to
  simulate a P&L distribution for VaR in a trading book, applied here to an insurer's unpaid
  claim liability.

## Data source

CAS (Casualty Actuarial Society) Loss Reserving Database, originally compiled from NAIC
Schedule P statutory filings. Retrieved via the `problemofpoints/reservetestr` R-package
GitHub repository, which mirrors the original (now offline) casact.org CSV files verbatim.
